# UltraQA — 自动 QA 循环

在代码改动后进入**自主验证循环**：运行质量门禁 → 失败则诊断根因 → 修复 → 重跑，直到目标达成或达到退出条件。

> 参考：yeachan-heo/oh-my-claudecode 的 ultraqa（QA cycling workflow），按 MyYoda 流程适配。

## 目标解析

| 参数 | 目标类型 | 验证命令 |
|---|---|---|
| `--tests` | tests | 项目测试命令（MyYoda：`bun test`） |
| `--build` | build | 项目构建命令（`bun run build`） |
| `--lint` | lint | lint 命令（如有） |
| `--typecheck` | typecheck | 类型检查（`bun run typecheck`） |
| `--custom <pattern>` | custom | 运行合适命令并检查输出是否匹配 pattern |
| 无参数 | custom | 按用户意图解析目标 |

## 循环流程（最多 5 轮）

每轮：
1. **运行验证**：执行目标命令，捕获输出
2. **检查结果**：
   - 通过 → 输出成功信息，结束
   - 失败 → 进入第 3 步
3. **诊断根因**：阅读真实报错输出（不猜测），定位根因与修复建议
4. **修复**：按诊断精确修复（遵守 B1「先读后改/小步验证」纪律）
5. **重跑**：回到第 1 步

## 退出条件

| 条件 | 动作 |
|---|---|
| 目标达成 | 输出成功总结（第 N 轮通过） |
| 达到 5 轮 | 停止并输出诊断结论（不无限重试） |
| 同一失败出现 3 次 | 提前停止：根因未变，继续修复无意义，输出完整诊断 |
| 环境错误（命令不存在等） | 停止并说明环境问题 |

## 过程可见

每轮向用户输出进度：
```text
[QA 1/5] 运行 typecheck...
[QA 1/5] 失败 - 3 个类型错误
[QA 1/5] 诊断：auth.ts:42 缺少 null 检查
[QA 1/5] 修复：auth.ts
[QA 2/5] 运行 typecheck...
[QA 2/5] 通过
[QA 完成] 第 2 轮通过
```

## 原则

- **只跑项目自身命令**，不执行用户未要求的操作
- 诊断基于真实报错输出，不猜测
- 修复遵守项目规范（B1 编码纪律、code-review 自查）
- 达到退出条件必须停止，不无限循环
