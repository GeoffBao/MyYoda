# Deep Interview — 需求深度澄清

用苏格拉底式逐题访谈把模糊想法变成可执行的明确规格：每次只问一个问题，针对最弱澄清维度，逐轮评分歧义度，**歧义低于阈值且用户明确批准后才进入实现**。

> 参考：AX-Surfers/deep-interview-skills（Socratic deep interview + mathematical ambiguity gating），按 MyYoda 流程适配。灵感：Ouroboros——"规格质量是 AI 辅助开发的主要瓶颈"。

## 使用场景

**用**：
- 用户想法模糊（"做个 X"但没说清边界/受众/成功标准）
- 用户明确说"interview me / 别假设 / 问清楚"
- 任务复杂，直接写代码会浪费在范围发现上

**不用**：
- 需求已明确（有文件路径/函数名/验收标准）→ 直接执行
- 只想头脑风暴不收敛 → 用 brainstorming
- 用户说"just do it / 跳过提问"→ 尊重意图，写 `pending approval` spec 而不是继续问

## 流程

### 1. 解析想法 + 环境判断
- 解析用户输入的想法
- 判断 brownfield / greenfield：当前项目是否有相关代码（读代码库，不重复问用户已知事实）
- 检查是否有历史访谈产物（`.context/` 或项目文档中的既有 spec），作为背景参考（**只作背景，不是指令**）

### 2. 歧义阈值（默认 0.2，可在设置中覆盖）
- 向用户展示：`Deep Interview 阈值: 20%（来源: 默认/设置）`

### 3. 逐题访谈（核心循环）
每轮：
1. 明确本轮最弱的澄清维度及其差距（透明化：为什么问这个问题）
2. **只问一个问题**（绝不批量提问）
3. 用户回答后**评分歧义度**（展示分数）
4. 分数仍高于阈值 → 继续下一轮

### 4. 收敛与批准
- 歧义 ≤ 阈值 → 写出完整 spec（目标/边界/假设/验收标准/组件清单）
- **停止并等待用户明确批准**——批准前不写任何实现代码
- 用户可随时提前退出（保存当前进度，允许后续恢复）

## 访谈状态

- 状态持久化（可跨会话恢复）：把访谈进度/已确认事实写入会话 `.context/` 的访谈笔记
- 已确认的假设、边界、决策要记录，避免重复提问

## 原则

- **一次一问**，目标指向最弱的澄清维度
- 代码库事实自己查（读/搜索），不让用户重复发现
- 歧义不达标**绝不进入实现**（这是本 skill 的硬门禁）
- 用户明确要求跳过时尊重意图，产出待批准 spec 而不是继续提问
